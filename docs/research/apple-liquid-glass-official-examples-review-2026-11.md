# Official Apple Liquid Glass examples: fresh review

Checked November 8, 2026 against Apple sources. The six existing showcase scenes cover part of Apple's interaction language. They do not establish one-to-one coverage. The missing families include background extension, independent glass identities and unions, responsive toolbar policy, inactive windows, nonmodal presentations, and several search placements.

This report contains 55 baseline behavior cases and four additional-platform or provisional cases. “Present” means source code contains a relevant demonstration. “Partial” means a related component exists but the named Apple behavior is absent or unproved. “Missing” means I found no matching demonstration in the inspected showcase. These are source observations, not new runtime verification.

## Versions and evidence boundaries

Apple's current public pages name [iOS 27](https://www.apple.com/os/ios/) and [macOS 27 Golden Gate](https://www.apple.com/os/macos/). [Apple Design Resources](https://developer.apple.com/design/resources/) lists iOS/iPadOS 27 and macOS 27 kits. The 2025 videos remain useful for the original public APIs; current references and 2026 sessions take precedence when the design or spelling changes.

The current reference uses [`toolbarMinimizationBehavior(_:for:)`](https://developer.apple.com/documentation/swiftui/view/toolbarminimizationbehavior(_:for:)) and `ToolbarMinimizationBehavior`. WWDC26 uses the earlier `toolbarMinimizeBehavior` spelling. The reference specifies navigation-bar minimization, integrated top-tab minimization, and automatic safe-area adjustment. Do not copy the earlier spelling into a new SDK contract without compiling against that SDK.

Some returned documentation carries a **Beta** banner even though public OS pages name the 27 generation. In particular, [`TabRole.prominent`](https://developer.apple.com/documentation/swiftui/tabrole/prominent) was explicitly marked Beta. It is separated below. A design demonstration is evidence of behavior; it does not establish deployment availability for every public symbol.

Only `developer.apple.com`, `apple.com`, and `support.apple.com` are used as Apple evidence. Search results from developer-forum participants were excluded from capability claims. Several documentation pages return a JavaScript shell to the reader; their indexed Apple content was readable through search. The reader rejected Apple's linked Markdown representation as an unsupported content type. I did not download or build the Landmarks sample, inspect SDK headers, or run a simulator in this review.

[`backgroundExtensionEffect()`](https://developer.apple.com/documentation/swiftui/view/backgroundextensioneffect()) duplicates mirrored copies around available safe-area edges, blurs them, and clips them to avoid overlapping copies. Apple recommends discretion and generally one background instance. The UIKit and AppKit equivalents are `UIBackgroundExtensionView` and `NSBackgroundExtensionView`, documented together in the [adoption guide](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass). It is not a universal `overflow: visible` rule.

## Public capability versus renderer parity

| Platform | Publicly documented integration | What glasscn can establish from the inspected source |
| --- | --- | --- |
| SwiftUI | `glassEffect`, shapes, tint/interactivity, `GlassEffectContainer`, identities, union and transition values. [Custom glass guide](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views) | Expo system surfaces use Apple's renderer, but the current React API does not expose every SwiftUI integration behavior. A new bridge needs build and runtime evidence. |
| UIKit | `UIGlassEffect` and `UIGlassContainerEffect` use `UIVisualEffectView`. [UIGlassEffect](https://developer.apple.com/documentation/uikit/uiglasseffect), [UIGlassContainerEffect](https://developer.apple.com/documentation/uikit/uiglasscontainereffect) | Native surface/container wrappers are relevant. They do not automatically provide system navigation, search, toolbar policy, or presentation ownership. |
| AppKit | `NSGlassEffectView` has content, corner radius, style, tint and interactive response; a separate container combines effects. [NSGlassEffectView](https://developer.apple.com/documentation/appkit/nsglasseffectview), [NSGlassEffectContainerView](https://developer.apple.com/documentation/appkit/nsglasseffectcontainerview) | No AppKit target was inspected. Native iOS evidence must not be described as macOS native parity. |
| Browser | Apple's cited documentation does not provide a web Liquid Glass compositor API. | `GlassEffects`/CSS/SVG approximate observable behavior. Exact shader, background analysis, device-motion optics and material coefficients remain unverified. |

[`UIVisualEffectView`](https://developer.apple.com/documentation/uikit/uivisualeffectview) is the integration authority for effect content and rendering constraints. Keep native content in `contentView`; treat fading an effect or an ancestor as unsupported for this library. Foreground dimming for inactive windows must not become ancestor opacity on glass. The distinction between optical materialization and hiding a whole presentation should remain explicit in native APIs.

Neither the inspected first-party material description nor the public customization APIs publish Apple's complete refraction shader, diffusion kernels, opacity tables, optical index, spring constants, or all size-dependent coefficients. “One to one” is testable for public control behavior and platform-owned rendering. Pixel-identical web rendering is not established by choosing similar numerical tokens.

## Concrete additions to close the baseline gaps

1. Add a Landmarks composition with image-only mirrored extension, horizontal rows under sidebar/inspector, selection-linked inspector, and identified badge insertion/removal. Compare that to named unions rather than treating every merge as the same operation.
2. Add a resizeable toolbar composition with priority, explicit overflow-only actions, pinned Share, avatar background opt-out, and navigation-bar/safe-area minimization. Keep current API spelling tied to the SDK build.
3. Add Notes formatting as a nonmodal system sheet, plus anchored/centered action-sheet comparison and partial-to-full sheet capture. Exercise parent interaction, save/discard, dismissal, and focus return.
4. Add search comparisons for destination versus immediate input, inline scope, split-view toolbar search and sidebar search. Include the same recent/suggestion/filter/no-results states in each relevant placement.
5. Add a state matrix for regular/clear/standard material, small/large geometry, inactive/active windows, semantic foreground, contrast, borders, reduced highlights/motion/transparency, and clarity endpoints. Capture browser and native results separately.

No product source changed and no repository verifiers ran for this research-only review. Runtime, physical-device, AppKit, tvOS, spatial, VoiceOver, and SDK availability validation remain separate evidence to collect during implementation.
