# Apple Liquid Glass criteria (iOS/iPadOS 27, macOS 27)

Compiled 2026-11-08 for the independent UI/UX review. Each row restates one case ID from [apple-liquid-glass-official-examples-review-2026-11.md](../../apple-liquid-glass-official-examples-review-2026-11.md) as something a reviewer can observe, using only sources fetched today from developer.apple.com, apple.com and support.apple.com. That file's "existing illustration and remaining gap" column was not used.

## How sources were accessed

- HIG pages and developer documentation: the HTML pages are JavaScript shells, so every one was read through the DocC JSON endpoint (`https://developer.apple.com/tutorials/data/design/human-interface-guidelines/<page>.json` and `https://developer.apple.com/tutorials/data/documentation/<path>.json`). Image alt text inside that JSON was used where the rule lives in a screenshot (Notes Done button, MiniPlayer, Destination Video). Platform availability comes from the JSON `metadata.platforms` field. No fetched reference page carries a `beta` flag today.
- WWDC videos: the `/videos/play/...` pages serve the full transcript with per-sentence `data-start` times, the chapter list and the Code tab with snippet times. Timestamps below are transcript sentence times, not chapter starts, unless marked "chapter".
- apple.com: `/os/ios/` and `/os/macos/` (iOS 27, macOS 27 Golden Gate). [Apple Design Resources](https://developer.apple.com/design/resources/) lists iOS 27 and iPadOS 27 and macOS 27 UI kits.
- support.apple.com: iPhone User Guide "Adjust iPhone display and text settings", article 111773 (display accommodations), and the macOS 27 User Guide "Change Display settings for accessibility".
- No request carried identifying headers. Nothing was built, run or downloaded beyond page text.

Classification labels:

- **Requirement**: stated in the HIG or as an API reference contract.
- **Example**: shown or narrated in an Apple session or sample app, not written as a rule in the HIG or reference.
- **Provisional**: Apple describes the behavior but the testable detail (a UI label, a coefficient, an API name) is not published, or the guidance conflicts between Apple sources.

Video shorthand used in the source column: "Meet" = [Meet Liquid Glass, WWDC25 219](https://developer.apple.com/videos/play/wwdc2025/219/); "UIKit25" = [Build a UIKit app with the new design, WWDC25 284](https://developer.apple.com/videos/play/wwdc2025/284/); "SwiftUI25" = [Build a SwiftUI app with the new design, WWDC25 323](https://developer.apple.com/videos/play/wwdc2025/323/); "SOTU26" = [Platforms State of the Union, WWDC26 102](https://developer.apple.com/videos/play/wwdc2026/102/); "SwiftUI26" = [What's new in SwiftUI, WWDC26 269](https://developer.apple.com/videos/play/wwdc2026/269/); "UIKit26" = [Modernize your UIKit app, WWDC26 278](https://developer.apple.com/videos/play/wwdc2026/278/); "AppKit26" = [Modernize your AppKit app, WWDC26 289](https://developer.apple.com/videos/play/wwdc2026/289/); "Search26" = [Design intuitive search experiences, WWDC26 292](https://developer.apple.com/videos/play/wwdc2026/292/); "Lab26" = [SwiftUI Group Lab, WWDC26 8120](https://developer.apple.com/videos/play/wwdc2026/8120/). ## Criteria by case

### Material and foreground

| ID | Criterion (what a reviewer should observe) | Class | Source and section or timestamp | Version and status | Notes |
| --- | --- | --- | --- | --- | --- |
| M01 | Regular glass over a light backdrop reads lighter and over a dark backdrop reads darker. Content behind is blurred and luminosity-shifted so text on the surface stays legible. Text-heavy surfaces (alerts, sidebars, popovers) use regular, never clear. A scroll edge effect under the bar blurs and fades content further. | Requirement | [HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials), "Liquid Glass", regular-variant paragraph and images `materials-ios-liquid-glass-over-dark/-over-light` | `Glass.regular` iOS/iPadOS/macOS/tvOS/watchOS 26.0+ (not visionOS). HIG Materials last changed September 9, 2025; no 2026 revision. | Matches catalogue. The 27 refinements (stronger diffusion, darkened edge, brighter speculars) are only in SOTU26 and apple.com, not in this HIG page. See NF01. |
| M02 | Clear glass appears only over photos or video. Over bright media a dark dimming layer sits behind the glass at about 35% opacity; over dark media, or when AVKit's own playback dim is present, no extra dim is added. Labels on clear glass are bold and bright. Regular and clear are never mixed in one composition. Clear does not adapt (no light/dark flip). | Requirement | HIG Materials, "Liquid Glass", clear-variant bullets; [Meet 13:51-15:08](https://developer.apple.com/videos/play/wwdc2025/219/?time=831) (three conditions at 14:50); [`Glass.clear`](https://developer.apple.com/documentation/swiftui/glass/clear) Discussion | iOS 26.0+ | Apple's own sample in the `Glass.clear` reference uses `.background(.black.opacity(0.3))`, 30% rather than the HIG's 35%. Treat 35% as the design guidance and 30% as sample code. Meet 14:37 also allows localized dimming behind small clear elements. |
| M03 | Content-layer surfaces (app backgrounds, cards, table views) use standard materials, not Liquid Glass. iOS offers four thicknesses: ultra-thin, thin, regular (default), thick. Labels on materials use vibrancy levels label, secondaryLabel, tertiaryLabel, quaternaryLabel; quaternary is avoided on thin and ultraThin. | Requirement | HIG Materials, "Standard materials" and "Platform considerations > iOS, iPadOS"; [Meet 13:04-13:24](https://developer.apple.com/videos/play/wwdc2025/219/?time=784) (table view stays in content layer) | Long-standing | [Lab26 9:37-10:15](https://developer.apple.com/videos/play/wwdc2026/8120/?time=577) repeats it for 27: content layer stays flat; glass with nothing scrolling under it adds nothing. |
| M04 | A glass element that grows (toolbar button opening its menu) looks like thicker material at the larger size: deeper and richer shadow, stronger lensing and refraction at the rim, softer light scatter. Shrinking back reverses it. A reviewer compares the same surface at button size and menu size. | Example | [Meet 7:02-7:25](https://developer.apple.com/videos/play/wwdc2025/219/?time=422) ("Adaptivity" chapter); [UIKit25 21:30-21:44](https://developer.apple.com/videos/play/wwdc2025/284/?time=1290) (larger is more opaque, smaller is clearer and flips light/dark) | iOS 26+, system-rendered | Timestamp confirmed. Apple publishes no shadow, refraction or scatter coefficients. |
| M05 | Small bars (navigation bar, tab bar, toolbar) flip between light and dark glass as the content behind changes, and their glyphs flip with them. Large surfaces (menus, sidebars) adapt tint but do not flip light/dark, and look more opaque. | Requirement | [HIG Color](https://developer.apple.com/design/human-interface-guidelines/color), "Liquid Glass color", second paragraph; [Meet 15:16-15:51](https://developer.apple.com/videos/play/wwdc2025/219/?time=916) | iOS 26+. HIG Color last changed December 16, 2025. | Catalogue timestamp `time=894` (14:54) lands on the clear-glass conditions. The small/large distinction starts at 15:16. |
| M06 | Only the primary action is tinted, and the tint goes on the glass background, not the glyph. Notes' Done button: yellow glass with a white checkmark at default contrast; under Increase Contrast a darker yellow with a black checkmark. In a toolbar only Done carries the accent color. A selected tab's symbol and label can be colored. | Requirement | HIG Color, "Liquid Glass color" (alt text of `color-context-light-mode`, `color-context-light-mode-high-contrast`, `colors-liquid-glass-usage-correct/-incorrect`, `color-liquid-glass-overview-color-over-tab-bar`); [HIG Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars), "Actions" (one `.prominent` action, trailing side); [Meet 17:21-17:49](https://developer.apple.com/videos/play/wwdc2025/219/?time=1041) | iOS 26+ | Confirmed. Meet 16:31 says tint generates a tone range mapped to backdrop brightness; a flat fill reads as opaque and is shown as the wrong example at 17:03. |
| M07 | A label inside a glass effect's content view turns vibrant on its own, based on its semantic color (`secondaryLabel` in Apple's example). When the backdrop changes, glass and label switch light/dark together, provided dynamic colors are used. | Example | [UIKit25 code "Adding content to glass views" 21:49](https://developer.apple.com/videos/play/wwdc2025/284/?time=1308), narration 21:48-22:12; [SwiftUI25 18:43](https://developer.apple.com/videos/play/wwdc2025/323/?time=1123) (vibrant text color in `glassEffect`) | iOS 26+ | Confirmed, including `label.textColor = .secondaryLabel`. |
| M08 | Glass press response is stronger for direct touch and more subdued for trackpad. On macOS 27, interactive glass gets a subtle click bounce tuned for the pointer. | Requirement | [HIG Motion](https://developer.apple.com/design/human-interface-guidelines/motion), opening paragraph; [SwiftUI26 2:35-2:47](https://developer.apple.com/videos/play/wwdc2026/269/?time=155); [AppKit26 15:01-15:27](https://developer.apple.com/videos/play/wwdc2026/289/?time=901) | HIG Motion changed September 9, 2025. macOS bounce is new in macOS 27. | HIG states the behavior with no magnitudes. AppKit26 limits the bounce to controls, buttons and glass containers of interactive controls. |

### Combining and transitioning glass

| ID | Criterion | Class | Source and section or timestamp | Version and status | Notes |
| --- | --- | --- | --- | --- | --- |
| G01 | Glass siblings in one container render from a shared sampling region. As two shapes come within the container spacing their outlines blend like droplets; a larger spacing starts the blend sooner; container spacing larger than the stack spacing keeps them merged at rest. Each button stays independently tappable. Nearby glass in separate containers looks inconsistent because glass cannot sample other glass. | Requirement | [`GlassEffectContainer`](https://developer.apple.com/documentation/swiftui/glasseffectcontainer) Overview; [Applying Liquid Glass to custom views](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views), "Combine multiple views"; [SwiftUI25 19:51-20:35](https://developer.apple.com/videos/play/wwdc2025/323/?time=1191) ("glass can not sample other glass" 20:15); [UIKit25 23:52-24:57](https://developer.apple.com/videos/play/wwdc2025/284/?time=1432) | iOS/iPadOS/macOS/tvOS/watchOS 26.0+, not visionOS | UIKit25 24:46: the container also enforces uniform adaptation across its members. |
| G02 | Landmarks badges: badges and the show/hide button live in one container, each with a `glassEffectID` in a shared namespace, toggled inside `withAnimation`. Expanding, the badges separate out of the button like liquid; collapsing, they are reabsorbed. Badges are regular glass in a rounded rect; the button uses `.buttonStyle(.glass)`. | Example | [Landmarks: Displaying custom activity badges](https://developer.apple.com/documentation/swiftui/landmarks-displaying-custom-activity-badges), "Animate the badges using the morph effect" | Sample metadata: iOS/iPadOS/macOS 27.0, Xcode 27.0 | The sample shows expand/collapse of the earned-badge stack. It does not show a single badge being earned and inserted, which the catalogue implies. |
| G03 | Two glass shapes that share an ID namespace inside one container morph into each other during an animated state change, rather than one fading out and the other fading in. IDs have no effect outside transitions and animations. | Requirement | [`glassEffectID(_:in:)`](https://developer.apple.com/documentation/swiftui/view/glasseffectid(_:in:)) Discussion; custom-views guide, "Morph Liquid Glass effects during transitions" | iOS 26.0+ | Confirmed. |
| G04 | Views with the same union ID, the same shape and the same glass variant render as one glass shape even at rest and even outside a stack. Two union IDs in one container render as two shapes (guide example: four symbols, two capsules). | Requirement | [`glassEffectUnion(id:namespace:)`](https://developer.apple.com/documentation/swiftui/view/glasseffectunion(id:namespace:)) Discussion; custom-views guide, `glassEffectUnion` example | iOS 26.0+ | Confirmed. |
| G05 | `matchedGeometry` (default for effects within container spacing) grows an appearing shape out of a nearby shape's geometry. `materialize` fades content and animates the glass material in or out with no geometry match (for effects farther apart than the spacing). `identity` applies no change. Appearance and removal modulate lensing, not just alpha. | Requirement | [`GlassEffectTransition`](https://developer.apple.com/documentation/swiftui/glasseffecttransition) and its `identity`, `materialize`, `matchedGeometry` pages; custom-views guide, "Morph"; [Meet 2:55-3:06](https://developer.apple.com/videos/play/wwdc2025/219/?time=175); [UIKit25 23:21-23:35](https://developer.apple.com/videos/play/wwdc2025/284/?time=1401) (set the effect to nil, not alpha) | iOS 26.0+ | Guide: "The system applies more than opacity changes with the available transition types." |
| G06 | An interactive glass button is a system glass or glassProminent button (with `buttonBorderShape` for circles), not a glass effect wrapped around a plain button. Toolbar buttons already have glass; adding another layer is wrong; color comes from tint. | Example | [Lab26 10:29-11:42](https://developer.apple.com/videos/play/wwdc2026/8120/?time=629) (question chapter 7:21); [Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass), "Controls", "Leverage new button styles" | `glass`, `glassProminent` iOS 26.0+ | The catalogue's 7:21 is the chapter start for the question. The "button on glass" warning is at 10:50-11:00. |

## Fidelity reference

These are the published numbers and rules a reviewer can hold a web or React Native recreation to. Unless a row says otherwise the source is the HIG page named, read through the JSON endpoint on 2026-11-08.

### Materials

- Two Liquid Glass variants, regular and clear, never mixed. Regular blurs and shifts luminosity; clear is highly translucent and needs a dim layer over bright media: 35% dark ([HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials)). Apple's `Glass.clear` sample uses 30% black.
- Standard materials for the content layer on iOS: ultra-thin, thin, regular (default), thick. Vibrancy: label, secondaryLabel, tertiaryLabel, quaternaryLabel; fill, secondaryFill, tertiaryFill; one separator level.
- Small bars flip light/dark; large surfaces are more opaque and don't flip ([HIG Color](https://developer.apple.com/design/human-interface-guidelines/color)).
- iOS 27 user control: Settings > Appearance > Liquid Glass slider, ultra clear to fully tinted, locked by Reduce Transparency or Increase Contrast (support.apple.com).
- **Not published**: blur radii, refraction index, specular intensity, shadow opacity tables, tint tone curves, the slider's endpoint values, spring constants, or any size threshold for the thickness change.

### Sheets

- Detents: large is fully expanded, medium is about half of that. A sheet always supports large; medium-only prevents full height. Include a grabber on resizable sheets; it cycles detents on tap and works with VoiceOver ([HIG Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)).
- Partial-height sheets are inset glass with bottom corners pulled in to the display curve; at full height the glass goes opaque and the sheet meets the screen edges; corner radius is increased ([Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass), SwiftUI25 6:26).
- Cancel leading, Done trailing; Done needs Cancel or Back; never all three (March 24, 2026).
- iPad: prefer page or form sheet styles, centered over a dimmed background.
- **Not published**: sheet corner radius, inset distance, medium detent exact height.

### Tab bars

- iOS: floats at the bottom on glass; may minimize on scroll with the accessory moving inline; exit minimization by tapping a tab or scrolling to top; dedicated search tab at the trailing end ([HIG Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)).
- iPadOS: tab bar near the top, optionally convertible to a sidebar; five or fewer default tabs when customizable.
- Icons above labels in compact width, side by side in regular width; prefer filled symbols; single-word labels; badges are red ovals with white text.
- Prominent tab (27): one per bar, trailing position, stays visible when the bar collapses (UIKit26 10:57).
- tvOS tab bar height **68 pt**, top edge **46 pt** from the screen top (published, tvOS only).
- **Not published**: iOS tab bar height, capsule radius, minimized size.

### Toolbars

- Image buttons share one glass background; text buttons, Done/Close and prominent buttons each get their own; fixed spacers split groups; flexible spacers split backgrounds unless told not to (UIKit25 7:33-9:35).
- At most about three groups; leading edge for back and sidebar toggle, center for common controls, trailing for important items, inspectors, search, More, and the single prominent action ([HIG Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)).
- Titles under 15 characters. System symbols without circle outlines. Monochrome labels by default; color only for meaning.
- 27 policy: visibility priority, overflow-only items, pinned trailing placement, navigation bar minimization (T03 to T06).
- **Not published**: iOS navigation bar or toolbar height, button diameter, inter-group spacing.

### Search fields

- Elements: leading magnifier, placeholder, clear button once text is entered, iOS Cancel while focused (Search26 1:42).
- Placement sets material: glass in a toolbar, content styling inline (Search26 2:17).
- Bottom toolbar field rises above the keyboard; inline field stays at the top.
- Dedicated search area on iPad/Mac: focus the field on arrival, except on iPad with only a virtual keyboard ([HIG Search fields](https://developer.apple.com/design/human-interface-guidelines/search-fields), "iPadOS, macOS").

### Sliders, toggles, segmented controls

- Thumbs and knobs lift into glass only while interacting (HIG Materials; UIKit25 17:43).
- UISwitch sizes changed slightly in 26; Apple gives no new numbers (UIKit25 17:35).
- Switch only in list rows on iOS; outside a list use a toggle button; default green, or the accent color with enough contrast ([HIG Toggles](https://developer.apple.com/design/human-interface-guidelines/toggles)).
- Segmented controls: about five segments maximum on iPhone, five to seven on wide layouts; equal widths; text or images, not both ([HIG Segmented controls](https://developer.apple.com/design/human-interface-guidelines/segmented-controls)).
- Minimum on the leading side, maximum on the trailing side; don't use a slider for volume on iOS ([HIG Sliders](https://developer.apple.com/design/human-interface-guidelines/sliders)).

### Menus

- iOS/iPadOS layouts: small (row of four icon-only items on top), medium (row of three icons with short labels), large (default list) ([HIG Menus](https://developer.apple.com/design/human-interface-guidelines/menus)).
- Icons sparingly; all or none within a group; standard icons for standard actions (June 8, 2026). Menu bar images hidden by default on iPadOS/macOS 27.
- Submenus one level deep, about five items or fewer.

### Sidebars

- 2026 revision (June 8, 2026): icons default to the app accent color, which follows the macOS system accent; fixed colors used sparingly. Extend rich content beneath by scrolling or background extension. Show at most two levels of hierarchy ([HIG Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)).
- 27: sidebars reach the window edges on iPad and Mac; macOS selection is semibold (SOTU26 23:36, AppKit26 14:42).
