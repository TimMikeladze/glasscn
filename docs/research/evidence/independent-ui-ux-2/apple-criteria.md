# Apple criteria for the Liquid Glass catalogue

Fetched 2026-11-08. Covers the 59 case IDs in [apple-liquid-glass-official-examples-review-2026-11.md](../../apple-liquid-glass-official-examples-review-2026-11.md). Only the Apple side was checked; the catalogue's "existing illustration and remaining gap" column was ignored.

## Method

- Documentation and HIG pages were fetched as DocC JSON with plain `curl` (default curl user agent, no extra headers) from `https://developer.apple.com/tutorials/data/<path>.json`: 98 documentation pages and 14 HIG pages, all fetched fresh for this file. Availability comes from each page's `metadata.platforms`. None of the fetched pages has `"beta": true` in its platforms or references on this date.
- WWDC video pages were fetched as HTML. Chapters, the code index and the transcript were read from the `chapter-item`, `sample-code-main-container` and `data-start` markup. Timestamps below are the transcript sentence times, not just chapter starts.
- `www.apple.com/os/ios/`, `www.apple.com/os/macos/`, `developer.apple.com/design/resources/` and one `support.apple.com` guide page were fetched as HTML.
- A 404 from the JSON endpoint is recorded as "not in the reference", which is different from an inaccessible page. Every page cited below returned 200. No case is inaccessible.
- Semantic color values that Apple does not publish on the web were read from the SDK at runtime: a UIKit program run with `simctl spawn` in the already-booted iOS 27.0 simulator (runtime 24A434, Xcode 27.2 build 27B52), and an AppKit program on the host (macOS 27.2). These are labeled "SDK" and are **not** web evidence.

Class: "Requirement" means Apple-documented guidance or an API contract in the HIG or reference. "Example" means a pattern Apple demonstrates in a sample, a session or a first-party app, without stating it as a rule.

### Hit targets and contrast

- [HIG Buttons, Best practices](https://developer.apple.com/design/human-interface-guidelines/buttons#Best-practices): a button needs "a hit region of at least 44x44 pt", and 60x60 pt in visionOS.
- [HIG Accessibility, Mobility](https://developer.apple.com/design/human-interface-guidelines/accessibility#Mobility), default and minimum control size: iOS and iPadOS 44x44 pt and 28x28 pt; macOS 28x28 pt and 20x20 pt; tvOS 66x66 and 56x56; visionOS 60x60 and 28x28; watchOS 44x44 and 28x28. Leave about 12 pt of padding around bezeled elements and about 24 pt around elements without a bezel.
- [HIG Accessibility, Vision](https://developer.apple.com/design/human-interface-guidelines/accessibility#Vision): Accessibility Inspector applies WCAG AA. Text up to 17 pt, any weight: 4.5:1. 18 pt, any weight: 3:1. Bold, any size: 3:1. If the default colors fall short, provide a higher-contrast scheme under Increase Contrast, and check both light and dark.
- [HIG Dark Mode, Dark Mode colors](https://developer.apple.com/design/human-interface-guidelines/dark-mode#Dark-Mode-colors): never below 4.5:1. For custom foreground and background colors, aim for 7:1, especially for small text.
