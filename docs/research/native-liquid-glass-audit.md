# Native Liquid Glass audit

Audited 2026-11-08 against the checkout at `d896a3d`. This records the implementation before the 27 rebuild. Findings below are source observations, not claims that a device was tested. All 92 native TSX files were inventoried; optical, navigation, overlay, control and accessibility paths received detailed source review. Chart mathematics and unrelated application logic were outside this material audit.

## Sources and platform boundary

The sandbox declares Expo 57, React Native 0.86.3, `expo-glass-effect ~57.0.4` and `@expo/ui ~57.0.21` in `sandbox/native/package.json`. Native dependencies were absent when this audit started. To avoid trusting remembered API shapes, the exact [expo-glass-effect 57.0.4 tarball](https://registry.npmjs.org/expo-glass-effect/-/expo-glass-effect-57.0.4.tgz) and [Expo UI 57.0.21 tarball](https://registry.npmjs.org/@expo/ui/-/ui-57.0.21.tgz) were read directly. The tarballs agree with the [SDK 57 GlassEffect reference](https://docs.expo.dev/versions/v57.0.0/sdk/glass-effect/) and [Expo UI reference](https://docs.expo.dev/versions/v57.0.0/sdk/ui/).

`GlassView` wraps UIKit `UIVisualEffectView` and `UIGlassEffect`. Its defaults are regular glass, automatic appearance, no tint and no interaction. `GlassContainer.spacing` controls when sibling effects begin merging. Style animation operates on the effect and takes seconds; omitting its duration lets the OS choose. The package's Swift implementation inserts children into `contentView`. A child scrim therefore paints **above** the effect, not behind the sampled media. See `package/src/GlassView.types.ts`, `package/ios/GlassView.swift` and `package/ios/GlassContainer.swift` in the pinned tarball.

Apple documents the [alpha/compositing restriction on UIVisualEffectView](https://developer.apple.com/documentation/uikit/uivisualeffectview). Keep glass and all its ancestors at opacity 1; animate effect materialization or geometry. The 57.0.4 implementation has a visibility retry, but that is not permission to rely on offscreen alpha compositing.

The shipping native target is iOS, Android and React Native Web. There is no React Native macOS/AppKit target or package in this repository. Its iPad treatment can follow iOS 27; macOS parity currently concerns the browser implementation and source guidance.

## Current Apple requirements

Apple's current [Materials HIG](https://developer.apple.com/design/human-interface-guidelines/materials) reserves Liquid Glass for controls/navigation over content. Regular is the general-purpose choice. Clear belongs over photos/video with bright, bold content. Consider a 35% dark dim behind clear controls over bright media; omit it over dark media or when AVKit already dims the content. Do not indiscriminately put regular and clear controls together.

[WWDC26 State of the Union](https://developer.apple.com/videos/play/wwdc2026/102/) shows 27's stronger diffusion, more defined edge/refraction treatment and the clarity preference. Mac/iPad sidebars now meet window edges and regain accent-colored symbols. Content scrolling beneath floating controls produces a uniform toolbar top. [What's new in UIKit](https://developer.apple.com/videos/play/wwdc2026/278/) explains that automatic scroll-edge appearance has its own visual treatment; it is not a soft/hard heuristic. Use system UI where available to inherit these changes.

Apple does not publish glass shader source, precise blur kernels, tint alpha, spring constants or refraction maps. Token values in this repo are glasscn values. Passing the system effect through unchanged is how native inherits Apple's current optics.

## Verification required after rebuilding

The existing Jest setup mocks both `expo-glass-effect` and every `@expo/ui` entry point to plain views (`sandbox/native/jest.setup.js:18–24`, `jest.expo-ui.js`). Its structural test can detect forbidden fading ancestors, and component tests can prove prop/path choices. Neither can prove refraction, vibrancy, native presentation or callback support in the actual package. The ignored system-menu callbacks illustrate that boundary.

Add regressions for untinted defaults/explicit tint, preference changes, hidden child/accessibility behavior, supported sheet path selection, initial detent and live detent notifications. Exercise custom drags while blocking the JS thread to prove the UI tracking path. Then inspect iOS 27 with photos/text moving under glass, native system controls, clear media controls, grouped morphs, sidebar/top-toolbar scroll and all accessibility modes. Compare light/dark and the largest supported Dynamic Type.

At audit time iOS 26.5 was booted and iOS 27.0 runtime `24A434` was installed with no booted 27 device. That is not iOS 27 visual evidence. `verify:native` plus mocked Jest is necessary install evidence; actual simulator/device images and interactions are still required. Physical-device performance, especially under load, remains separate from simulator fidelity.
