# React Native rules

1. **Same names, same palettes.** `native-tokens` mirrors the web palettes and token names as plain values; keep them in step when a palette changes.
2. **Two layers, like Apple's.** `Glass variant="material"` (default) is the content layer (cards, panes, grouped lists). It's a system material on iOS (every version), token `backdrop-filter` on the web, the Android blur tier inside `<GlassBlurTarget>`, otherwise a fill with no elevation. `variant="liquid"` / `"liquid-clear"` (or `interactive`) is the control layer (floating buttons, bars of controls, `GlassGroup`, menus). It's Liquid Glass (`expo-glass-effect`) on iOS 26, liquid frost tokens elsewhere. Inline controls (switch, segmented, inputs, toggles) are *fills*, not glass. **Never liquid in liquid:** a liquid `Glass` under another renders clear (its shape and tint only), because glass can't sample glass. Neighbours share one backdrop via `GlassGroup` / `GlassEffectGroup`. Under Reduce Transparency it falls back to `glassSolid`.
3. **Never fade Liquid Glass.** Expo documents that opacity 0 on a `GlassView` or any of its parents stops the glass rendering at all ([expo-glass-effect, known issues](https://docs.expo.dev/versions/latest/sdk/glass-effect/)), so a fade-in from 0 starts invisible. To bring glass in, translate or scale it, or materialise it with `glassEffectStyle={{ style, animate: true, animationDuration }}` (swap `"none"` ↔ `"regular"`, which is Expo's recommended fade). Never animate opacity on it or above it. Entrances, tab transitions and screen animations on iOS 26 check `canFade()`. `Press` only dims when asked, so a `Press` around `<Glass>` passes at most `dim={canFade()}`, and disabled glass dims its label, not its container.
4. **Tint Liquid Glass.** Untinted, it nearly vanishes on a pale aurora, so `Glass` lays in `glassTint` by default.
5. **Bars never use Liquid Glass.** Chrome that fades with scroll uses `bar` (UIVisualEffect blur).
6. **Every tappable is `Press`** (Reanimated, UI thread): solid squashes (`pressScale`), `liquid` grows (`pressGrow`), no opacity unless `dim`. Function-style `style` works. Haptics fire when the press lands, never on press-in: `haptic` on `Press`, or `haptics.selection() / impact() / notify()`; `setHapticsEnabled(false)` turns them all off; no-op on the web.
7. **Verify on a device class.** `pnpm verify:native` type-checks the install; behaviour needs the sandbox (`sandbox/native`, [`../sandbox.md`](../sandbox.md)) on the iOS 26 simulator.
8. **One file, every platform.** A component twin is plain React Native (no Tailwind, Radix or DOM) so react-native-web renders the same file on the web. Same exports, parts and variant props as the web file; `className` → `style`.
9. **State goes in `aria-*`** (add `accessibilityState` too if you like). React Native 0.86 reads both, but react-native-web drops `accessibilityState`, so `aria-checked`/`aria-selected`/`aria-expanded`/`aria-disabled` are the only way a switch or tab announces itself on the web.
10. **Every string inside `<Text>`.** Native throws on a bare string in a `View`; the web doesn't, so it only shows on a device. Wrap string children in `GText` (buttons, badges, cells), and render cell/header definitions yourself rather than through `flexRender` (which mounts them as components, so a returned string escapes the wrapper).
11. **Gestures are gesture-handler, motion is Reanimated.** No `PanResponder`, no RN `Animated` in rebuilt parts. Horizontal drags inside a ScrollView use `Gesture.Pan().activeOffsetX([-8, 8]).failOffsetY([-8, 8])`; commit on `onFinalize` so a cancelled drag still lands. Scratch state the gesture reads goes in a shared value via `.get()` / `.set()` (not `.value =`, not refs; the React Compiler lint rejects both). Positions animate `transform: translateX` in physical layout coordinates, so RTL rows need no flip; mirror value↔x for sliders with `I18nManager.isRTL`. The app root wraps `GestureHandlerRootView` + `KeyboardProvider`.
12. **Overlays are `Modal`s.** They float above every screen in a native stack, including screens pushed later, so don't open one on mount in a screen that stays mounted under others. The exception is the Toaster: on iOS it sits in a `FullWindowOverlay` (react-native-screens) so toasts show above modals and form sheets.
13. **Strip native-only props before they reach the DOM.** `Animated` adds `collapsable={false}`; on an SVG element react-native-svg passes it to the DOM. Wrap the animated SVG part and drop it.
14. **Accessibility settings come from `native-a11y` only.** `useReducedMotion / useReduceTransparency / useHighContrast / useBoldText`, `announce()` for live messages (FieldError, toasts), `hitSlop(h, w)` to grow anything under 44pt to a 44pt target, `MAX_FONT_SCALE` per text role. Layout uses `minHeight`, never `height`, so Dynamic Type can grow a control. No other `AccessibilityInfo` code, with two exceptions. Overlays move screen-reader focus to their title through `useInitialFocus` in `dialog`. The Toaster stretches its timeout on Android with `getRecommendedTimeoutMillis`.
15. **System controls first (`@expo/ui`).** Switch, single-value slider, plain-text segmented control and the date picker render the system control on iOS/Android (universal `@expo/ui` in `<Host>`, or `@expo/ui/community/*`), with the web's prop names. The RN version runs on the web, for prop combinations the system control can't do (ranges, ticks, icons, `onValueCommit`, …) and under `native={false}`. `swift-ui` / `jetpack-compose` imports live only in `.ios.tsx` / `.android.tsx` siblings.
    - **Menus.** DropdownMenu and ContextMenu read their own parts as data. When every part is plain (item text, `systemImage`, destructive, checkbox, radio, label, separator, sub-menu), they open the system menu via `@expo/ui/community/menu`. Any custom child, a controlled `open`, `native={false}` or the web falls back to the liquid-glass menu. Lucide icons only draw in the glass menu; the system menu takes an SF Symbol via `systemImage`.
    - **Bottom sheets.** These are the `@expo/ui` `BottomSheet`. A controlled `detent`, `onBeforeDismiss`, `modal={false}` or `native={false}` keeps the Reanimated sheet, because the system sheet can't do those.
16. **Forms wire themselves.** Inside a `Field`, Input/Textarea/InputGroupInput take the field's id (FieldLabel focuses and names them; outside a Field use `Label htmlFor`), its invalid state, and the description and error as their accessibility hint; FieldError announces itself once.
17. **Overlays share one entrance and one layer.** Menus, popovers, tooltips, sheets, dialogs, toasts, the dock, the toolbar and the search field are the control layer: `Glass variant="liquid"`. What sits inside them is fills, never more glass.
    - **Entrance.** Use `usePresence` + `useEntrance` from `dialog`: translate/scale, plus `Glass visible={open}` to materialise. Opacity only where `canFade()` allows.
    - **Keyboard.** Dialogs and sheets avoid it with `KeyboardAvoid`; the bottom search field rides it in a `KeyboardStickyView`.
    - **Safe area.** Read insets with `useInsets()`, which returns zero instead of throwing when there's no `SafeAreaProvider`.
    - **Scroll.** Bars that react to scroll read `ScrollEdgeProvider` / `useScrollEdge()`, not their own listener.
18. **Triggers take `asChild`.** `<DialogTrigger asChild><Button/></DialogTrigger>` merges the trigger into the child (Press `asChild`); without it a trigger around a Button nests two pressables and the inner one swallows the tap.
